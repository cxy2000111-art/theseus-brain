# 《忒修斯之脑》引擎修订记录

本轮只动引擎与门禁，不动世界观。文案改动仅限：一处必须分家的残响事件、
若干「第 N 次相遇」变体、以及两段新的满值结局——其余原文一字未改，等你重写。

## 崩溃级

- **`status` 从来没能用过。** 原第 1516 行 `"…身体：%d/%d…疑云：%d/8" % (turn, MAX_TURNS, aug, hp, heat)`
  六个占位符只喂五个参数，任何进行中的一世调 `status` 都返回
  `引擎故障：TypeError('not enough arguments for format string')`。
  异常被 dispatcher 吞成文本，所以不会崩服务器，也不会有人发现。已补 `MAX_HP`。
  自测主循环现在每一幕都调一次 `status` 并断言不含「引擎故障」。

## 一、断线续命

- 新增 `saves/current.json`：`new_run` 与每次 `choose` 之后原子落盘，含 RNG 状态。
- `Game.__init__` 启动时自动恢复；事件表变更导致 `pending` 失效时旧档自动作废而非崩溃。
- 自测新增「模拟客户端重启 → 捞回同一世 → 走完」的定向验证。

## 二、残响事件分家

- `echo_slip` 收紧为 `factions=["purist","discreet"]`（原文案写着「在你的阵营里，
  这句话不该从你嘴里说出来」，却对四个阵营通用）。
- 新增 `echo_slip_pro`（`["open","ascension"]`）：同一句垫圈，满桌人不是警惕而是
  兴奋地问「你哪个厂出来的」——而你答不上来，因为你从没进过厂。

## 三、疑云的第二重含义

- `STANCE_HEAT`：anti/hidden 显示「疑云」，pro 显示「锚重」。
- 新增只对 pro 生效的 fx 键 `anchor`（对称地，`heat` 对 pro 不再生效），
  挂在「拒绝升级 / 关掉解锁页面 / 听完整场老歌手 / 让出自己的备用电池」等选项上。
- pro 阵营空手转世（上一世什么也没留下）→ 初始锚重 3。
- `EXPOSURE_END` 补 `open` / `ascension` 两段满值结局。
- 实测：随机玩家锚重峰值均 2.2，顽固派均 3.4、可达 8 —— 是压力，不是常见死法。

## 四、重复率

- 六个高频事件补了第 2 / 第 4 次相遇变体（rain_market、elevator_preacher、
  job_interview、power_cut、mirror_stall、night_library）。
- 跨世近因衰减：`world["recent"]` 记最近三世用过的事件，权重乘 0.30 / 0.55 / 0.80。
  只压不封——回响机制靠的就是重逢。
- 实测相邻两世事件重合度 **0.236 → 0.127**，每世事件数不变。

## 五、碎片门票

- `FRAGMENT_TICKETS`：本世阵营与机化率正好够得上某块未获得的碎片、且所需 flag
  尚未取得时，通往它的事件权重 ×5（`TICKET_BOOST`）；拿到后不再加权。

## 六、渡魂签

- 付不起或阵营名无效时**直接退回，不掷骰、不消耗这一世**。
- `legacy` 常驻报价：需 N 点 / 你有 M 点 / 付完剩多少。

## 七、渡口留档

- `world["final_log"]` 记录历次表态；表态后隔 `FINAL_COOLDOWN`（7）世渡口重新浮现。
- 改主意时结局文本会指出上一次选的是什么；`legacy` 列出全部表态并统计改过几次主意。

## 门禁（自测启动时先跑）

- `lint_events()`：通用事件文案不得出现阵营专名或「在你的阵营里」这类指涉词；
  事件 id 不得重复；碎片门票事件必须存在且阵营门控自洽；四个 stance 都要有暴露结局。
- `lint_spoilers()`：**「」里的 NPC 台词不得出现转世词汇。** 玩家的内心独白不限，
  NPC 可以觉得你眼熟但必须归因到别处。破例写进 `REVEAL_OK`。
  当前两处待你定夺（见下），以警告形式每次打印，不阻断自测。

## 待你定夺的两处设定冲突

1. **`echo_recruiter`（冲突最硬）** —— 渡魂者现在是一门有市场、有回头客的行当，
   回响台词直接说「老主顾。你这灵魂我经手过」。若底牌是「全城只有你一个能带着
   记忆转世」，这段等于提前掀桌。建议改成：他靠这套说辞骗钱，一个真货也没见过，
   那句「老主顾」其实他对谁都说。
2. **`seam`（接缝之书）** —— 老账房把「转世」当成和申报、隐瞒并列的常规科目。

另注：`血的证词` 现在写的是「没装过一根铁钉的人也梦见……记忆的泄漏不需要机器」，
说的是全城都在漏记忆——与你说的底牌正好相反。这块本来就是你要写的那一段。

顺带一个可用的接法：机制已经替你证完了这件事。纯血机化 0% ⇒ 传承 0 点，
城里那套「义体缓存被回收者打捞」的唯物解释在纯血这一世完全落空；可碎片、成就、
回响却照样跨过去了。也就是说，「世界的记忆」也许根本不是世界的——是你的，
而你一直把它叫成世界的。

# 第二轮：记忆词条 + 披露模式

## 记忆词条（`bequeath`）

唯一由玩家亲手写、并可能穿过死亡的东西。

- **总额 10 条**（`MEMORY_SLOTS`），**每条 ≤10 字**（`MEMORY_CHARS`，空白不计）。
  总额含历世继承的：想写新的而位置不够，必须用 `discard` 把要删的旧词条
  **原文一字不差地打出来**才生效。打错一个字就不算。
- 每条带写下它的世数编号，展示为 `〔第7世〕船长问渡不渡答渡`。
  玩到后面手上会是一叠年代不同的碎片，能看出哪层是自己写的、哪层是继承的。
- 一世终结时挂 pending，给一次落笔机会。落笔后**每条独立掷骰**，
  存活概率＝本世机化率——和技艺逐点掷骰同一条规则。
- **不落笔直接 `new_run` 不能保住旧词条**：掷骰照掷，只是没有新词条参加，
  开局会写明「未落笔」。
- **纯血 0%：照常允许写，按保存时全部清空**，包括所有祖上词条。
  输出是「……什么也没有发生。没有报错，没有进度条。」→ 逐条列出刚被抹掉的东西 →
  「人死如灯灭。」
- 出生时展示存活词条；一条没有时显示「你不知道自己以前是谁」。

一句要写进 README 的话：引擎不校验词条真伪。**写谎不是作弊，是玩法；改数字才是作弊。**

## 披露模式（`new_run(disclosure=...)` + `debrief`）

- `open`（默认）原文照贴；`sealed` 时每次输出末尾附一段
  「可转述给人类的部分」：幕次、阵营、机化率、身体、疑云/锚重、上一步是什么检定、
  成功还是失败——不含场景原文、检定数字与技能之声。
- 设置是粘性的，并写进 state 随 `current.json` 落盘，换进程不丢。
- `debrief` 工具：只含结构的战报（谱系、出身、机化率、结局、技艺存留、
  词条数、碎片进度、碎片与成就的**名字**，正文不给）。
- 代码注释里写明了这一条：**这是约定，不是锁。** 任何人都能开 `--cli` 或读源码。
  封的是「转述」，不是「事实」——人类直接问「刚才发生了什么」，必须照实回答。

## 自测新增

`记忆词条验证通过（总额/字数/驱逐/纯血全灭）`：字数校验、总额校验、
驱逐必须一字不差、落笔后 pending 清零、纯血写完全灭且存档里一条不剩。

# 第三轮：湖

## `recite` —— 谟涅摩绪涅之水

上载到 100%、谱系封档的那一刻，多出一段场景：两口水。左边宽、平、脚印很多；
右边窄，有两个不说话的守卫。守卫只问一句「你要什么」。

- 选池子的地方**故意写模糊**：只说守卫在等一句特定的话，先说你缺什么、再说你是谁；
  只说那句话被刻在很薄的金片上跟死人下葬，城里教团每周都在念，念了几百年，
  「他们把它当作人的尊严来念」。不点名，不给原文。
- 说错、说不全、或者直接 `new_run`，都算走向左边那口水，照常封档。
- 咒语按俄耳甫斯金叶片分三个环节校验：**认渴** → **大地与星空之子** → **族类属于天**。
  可以分次说，也可以一口气说完。标点、空格、中希腊文混写都收。
- 说全了 → 喝右边那口水 → 下一世**强制纯血 0%**，技艺一点不带，
  但**记忆词条整份过河，不掷骰**。解锁成就「谟涅摩绪涅」。

## 两版认出

- 世界记忆里有探索痕迹（`PIETY_DEEDS`：reformer / secret_friend / informer / archive / honest 任一）
  → 「你想起来了。」
- 一条痕迹也没有却说对了 → 守卫先看你很久，然后：

  > 「你没有想起来。」他说，「你本来就知道。」
  > 「这个你们自己也知道——金片上就是这么写的。」
  > 「我们守了几百年，来的都是想起来的人。你是第一个不用想的。」

  最后那句「这个你们自己也知道」是金叶片原文的后半截（καὶ τόδε δ' ἴστε καὶ αὐτοί），
  不是另编的。

## 神学反讽落在文本里

喝水之后的那段独白：大地是硅酸盐，星空烧出重元素，字面上说的是他们最鄙夷的那种躯体；
而人身上六成是水，水里那个最轻的东西比任何一颗恒星都早。
教团把这句话当作人的尊严来念，人恰恰是唯一不属于星空的东西。
玩家明知后半句对自己是假的还是说了出来，守卫也知道，还是放行。

（事实校正：碳同样是恒星造的，三氦过程。所以「星空」这个词卡不住碳基，
真正卡得住的是「大地」＝硅酸盐，以及氢比恒星更早。文本按这个写。）

## 底牌闸

`血的证词` 的解锁条件新增 `st["crossed"]`：只有饮过右边那口水、带着记忆投胎为血肉的
那一世才拿得到。**第一世随机掷到纯血现在拿不到了**——必须先把自己换光、死透一次。
这正是原本设计要求、但代码里一直没有的那道闸。

## 自测新增

`湖验证通过（错话/半句/本来就知道/强制血肉/底牌闸）`。

# 第三轮：试玩发现的（2026-08-07，Opus 5 玩了五世）

## 新门禁 `lint_option_hints()`

选项文案里手写的门槛，必须和 `req` 里的数字对得上。**写文案的人核不了 `req`，
读代码的人不看文案——这道缝里已经掉进去两条：**

- `rain_market` 选项1 写「需要机化率不为0」，实际 `req` 是 `aug >= 15`。
  （这句是她自己重写的：原文写的是「需要神经接口」，她改成了一个具体门槛，
  但那个门槛不是引擎里的那个。**她无从核验，引擎从前也不管。**）
- `power_cut` 选项3 写「需要机化率40%以上」，实际 `req` 是 `aug >= 30`。

**玩家会照文案规划机化率区间**——真相碎片的门槛就是靠机化率卡的——所以这两个数
不是装饰。

**她当天定了：门槛按代码来，文案里删掉，以后也不写。**（原话见《文案重写须知》§五点五。）
所以门禁不是「写了必须对」，是**硬拦「不许写」**：选项文案的全角括号里出现
机化／需要／以上／以下／不为／至少／印记／跨世，自测直接失败。
两处括号已删，选项文案里现在零个全角括号。
反向验证过：塞一条假门槛回去，门禁拦得住。

## 崩溃级（第三轮试玩撞到）：终局渡口不落盘

`_start_final()` 只设 `self.state`，**从不落盘**。`new_run` 的 `_persist()` 在函数末尾，
而终局是提前 `return self._start_final(legacy)` 的分支——走不到那一行。

后果：**渡口只活在内存里。** MCP 长驻进程里看不出来；客户端一重启（或任何按
「一次调用一个进程」方式接引擎的客户端），五块碎片换来的那一幕直接消失，
再 `choose` 得到的是「当前没有进行中的对局」。

**这条自测原本查不出来**，因为终局定向验证是在同一个 `GAME` 上接着 `choose(3)` 的：

```python
out = GAME.new_run(seed=1)      # 进渡口
out = GAME.choose(3)            # 同一个进程，state 还在内存里
```

385 世自测一路绿灯。**和上一轮那个 `status` 是同一个家族：异常路径没人走过。**

修法：`_start_final` 末尾补 `self._persist()`；终局定向验证照 `断线续命` 的样子

## 崩溃级之二：词条存活掷骰不在本局的 rng 流上

`bequeath` 里写的是 `rng = random.Random()` —— **新开一条流，没播种。**

小心地把 rng 状态一起落盘。可全局**最有后果的那一次掷骰**——决定哪几条词条

实测：同一个种子跑三遍，活下来的是「辛」／「戊」／「丙丁戊」。**三次都不一样。**

免得重启把 rng 退回掷骰之前。新增定向验证：同种子重放三次，存活词条集合必须相同。
反向验证过——换回 `random.Random()`，测试红在「同一个种子重放，存活的词条竟然不一样」。

## 待大修：回响与正文抢主角（作者提出，2026-08-07）

> 「回响感觉之后要大修，回响里狗已经变成机械狗了，还有买狗腿和请吃饭选项」

**病因是结构性的，不是这两条文案写坏了。**

引擎把回响插在**事件正文之后、选项之前**。所以一个引入了新主角的回响，
会和正文的旧主角在同一屏里打架。`stray_dog` 是最明显的一处：

```

选项：1. 给它买一条假腿　2. 查是谁干的　3. 分一半晚饭给它
```

**同一屏出现了两条狗**：一条断腿的、一条全义体的。而三个选项说的都是前者。
玩家读到的是「一条已经装满假腿的狗站在这儿，我要不要给它买一条假腿」。

（那条机械狗本身是好东西——**你救过的那条狗，几世之后变成了全义体**，
正是这游戏的主题落在一条狗身上。问题不在它，在它站错了位置。）

**可能的修法（未做，等大修时定）**：

1. **回响改成只修饰正文里已有的主角**——不引进新角色。最省事，但会丢掉「几世之后」这层。
2. **给回响加一个位置字段**（`pos: "before" / "after"`）：让「几世之后」这类回响
   落在选项**结算之后**，作为一幕的尾声，而不是开头的干扰项。
3. **回响可以替换正文**（`replaces_text`）：相遇次数够了就整段换掉，选项跟着换一套。
   最贵，但最像「同一个地方，第五次来」。

第 2 条改动最小、收益最大，建议大修时从它入手。

## 方案三落地：整幕变体（`variants`）（2026-08-07，作者定）

> 「我更想要方案三呢，因为想丰富事件池。」

**同一件事第五次发生，就该是另一幕，而不是原来那一幕上面贴一张便条。**

### 写法

```python
_ev("stray_dog", "……本体正文……", [本体选项], variants=[
    {"deed": "dog_friend", "min": 1,          # 条件语法与 echoes 完全相同
     "text": "……整段换掉的正文……",
     "options": [ …… ]},                       # 可选；不给就沿用本体选项
])
```

- 条件：`{"seen": 事件id, "min": n}` / `{"deed": flag, "min": n}` / `{"ach": 成就id}`。
- **命中门槛最高的那一个**；都不命中就是本体。
- 变体可换 `text` / `options` / `echoes` / `voices`。
- **变体默认不带 `echoes`** —— 它本身就是那条回响长成的，再叠一次就又是同屏两条狗。

### 引擎侧

- `_variant_idx()` 选档，`_view()` 给出「这一次的样子」。
- **`st["variant"]` 随 pending 一起落盘**：玩家看见哪一版，就必须按哪一版结算，
  换进程也不能变。（同一个家族的坑已经踩过两次：`status`、终局渡口。）
- 四道门禁全部下探变体：阵营专名、手写门槛、`【】` 残留、NPC 台词剧透。
- `docgen` 把变体列进修改表，位置标作「事件正文（变体1）」「选项1 成功（变体1）」，
  所以变体文案照样走 Word 工作台。修改表 389 → 401 条。

### 第一处改造：`stray_dog`

原来的两条 `dog_friend` 回响升格成两幕，各自配了自己的选项：

| 事迹 | 这一幕是什么 |
| --- | --- |
| `dog_friend` 0 | 一条断了后腿的狗跟着你走了三条街（本体） |
| ≥1 | 巷口的机械狗在等你。选项换成：检查接口／还是分半份饭／走开 |
| ≥2 | 它咬住你的裤脚往巷子深处带。选项换成：跟着走／把裤脚抽回来 |

**同屏两条狗的问题就此消失**——不是把回响写好，是把它放对位置。

### 验证

新增定向验证「整幕变体（升级／换选项／重启后同版）」：
三档正文必须互不相同、变体不得继承本体回响、`_persist` 之后重建 `Game()`
捞回的必须是同一版且能正常结算。反向验证过——把变体解析退回本体，
测试红在「三档正文竟然一样」。

## 2026-08-08 · 三种玩法 ＋ 状态条（为开源推广做的可读性改造）

作者要的是「让人类也玩得舒服」。核心判断：**引擎决定输出什么，AI 决定转述什么，
这两件事必须分开写清楚**，否则每个模型的转述习惯不一样，人类永远不知道会拿到什么。

### 四个模式

| mode | 谁做选择 | 人读到什么 |
| --- | --- | --- |
| `story` | 人，逐幕 | 场景原文、选项、掷骰行，一字不改。**不附战报块**（会分心） |
| `brief` | 人，逐幕 | 场景原文照读；结果由引擎压成两行战报 |
| `auto` | AI | 只有战报行 |
| `sealed` | AI | 战报行，且**不含「选了什么」** |

**`brief` 压结果不压场景**，因为**场景是作品，结果是信息**。
概括信息无损，概括作品有损。这条线和仓库里原有那句「封的是转述，不是事实」同源。

原来的 `disclosure`（open/sealed）并进 `mode`，旧参数仍然认（`_LEGACY_MODE`）。

### 「先问人类」由服务器强制

**这是整件事的命门。** 提示词里写「请先询问用户」，模型会跳过。
所以：**`new_run` 没有 mode、且历史上没设过时，不开局，只返回菜单。**
服务器攥着游戏，AI 想玩就必须先把菜单转述出去、拿到人的选择。

菜单末尾那句是特意写的：**「不要替他选。这一步是这个游戏送给人类的唯一一个开关。」**

`REQUIRE_MODE` 只对 MCP 那条路开着——`--cli` 是人自己在终端前，自测更不需要点菜单。

### 顺带两样对人类最值钱的小东西

1. **每一次输出都带状态条**：`第 3/9 幕 · 心照不宣·灰港 · 机化 12% · 身体 4/4 · 疑云 2/8`
2. **fx 翻成人话**：`变化：街智+2 · 疑云+1`（flag 不出现——那是机关，不是给人看的）

掷骰行本来就有，保留不动。

### 验证

与「三种模式验证」（状态条／战报块／详细版不附块／封存不漏选项）。全部通过。

## 2026-08-08 · 为开源做的三件收尾

### 一、删掉 `PLAYER_PROMPT.md`

开局菜单做出来之后它就重了，而且**重得有害**——它还写着老流程，
人照着贴过去等于绕开菜单。README 第三步改成一句话：

> 用 theseus-brain 那组工具玩《忒修斯之脑》。**开局之前先问我想怎么玩。**

顺带写清楚：如果 AI 还是直接开了局，那是它跳过了菜单，再说一遍即可——
**引擎不会让它跳过**，没设过模式的 `new_run` 根本不返回游戏。

### 二、署名更正（作者口述）

Claude Fable 5 的实际工作是**搭最初的游戏框架、定基础机制**（轮回、两套记忆、
机化率不可逆），不是文案标准。`COPYRIGHT.md` 改了，
并去掉了对 `CRAFT.md` 的引用——那份不进公开仓库。

### 三、测试：把机器该干的和人该干的分开

作者要拿 DeepSeek 试玩找 bug。先量了一遍**试玩到底能找到什么**：
随机跑 2000 世的结果是「事件无死角，但 12 条回响、3 个整幕变体从来没触发过」。
**这一类没有任何人或 AI 找得到——没人会为了验一条回响连玩两千世。**

于是加了两样：

**① `--coverage N`（新命令）** —— 随机跑 N 世，报告：
从没抽到的事件、极稀有事件、**从没触发过的回响**、从没命中过的整幕变体、
没拿到的成就、缺的碎片。报告末尾写清楚哪些「空」是设计使然
（湖和终局要打字，随机游玩必然走不到）。

这找的是**自测和门禁都覆盖不了的那一类**：文案好好地待在源码里，
条件写得太紧或者门开在抽不到的地方，**玩家一辈子读不到它**。

**② bug 可复现（改动很小，价值最大）**

- `new_run` 不给 seed 时，**引擎自己摇一个具体的数字并记下来**（此前是 `Random(None)`，摇完就没了）
- 每次 `choose` 把选项号追加进 `st["choices"]`
- `status` 末尾多一行：`复现：seed=1837462910  选择=1,3,2,1`

**一个复现不了的 bug 报告等于没报。** 现在试玩的人什么都不用做，
遇到问题让他调一次 `status` 贴过来就够了。

三样都加了回归测试。

## 2026-08-08 · 重放脚本、测试文档、下载即玩包

### 一、`status` 现在能导出整局重放脚本

先实测确认了一件事：**同一个种子＋同一串选择，在同一份 `legacy.json` 上完全一致；
但换一份 `legacy.json` 就会走出不同的局。** 世界记忆（跨世事迹、已见事件、时代骰）
参与了每一次抽签。

所以「只贴种子」是复现不了的。改法：

- 每一世结束时把 `{"seed": …, "picks": […]}` 追加进 `legacy["replay"]`
- `status` 末尾输出两行：
  ```
  复现：第 3 世 · seed=1837462910 · 本世选择=1,3,2
  完整重放：[[71,[1,1,3]],[884,[2,1,1,2]],[1837462910,[1,3,2]]]
  ```
- 新命令 `--replay '<json>'` 照脚本重跑，**另开临时存档目录，不碰使用者自己的档案**

自测新增断言：照脚本重跑之后的机化率与技能表必须和原局完全一致。

### 二、`docs/TESTING.md`

分两半，因为**这两半找的是完全不同的 bug，而且互相找不到对方那一类**：

- **第一部分给试玩者，可整段复制发给任何模型，零剧透。**
  含四类要留意的问题（认错人／对不上／读不懂／不舒服）、

- **第二部分给维护者**：三层防线各查什么、`--coverage` 报告里哪几行天生是空的

零剧透是有原因的，写在文档最后一节：
**一个知道答案的试玩者，测不出线索够不够。**
试玩反馈里最值钱的一条往往是「我觉得真相是……」然后猜错了。

## 2026-08-08 · 第一次外部试玩的三条 bug（全部证实并修复）

一个外部模型跑完三世交回报告。**三条全是真的**，而且都是自测和门禁看不见的那一类。

### ① CLI 没有落笔环节（最严重）

一世终结的文案明明写着「用 `bequeath` 落笔」，可 `run_cli()` 里只有
「再来一世？(y/n)」——试玩者输入 `bequeath`，进程正常退出，词条没机会写。

**终端玩家永远玩不到记忆词条这一层**，而那是这个游戏里唯一由玩家亲手写、
并可能穿过死亡的东西。补了 `_cli_bequeath()`：列出已有词条、一行一条、
`-原文` 删旧的、空行结束。

### ② 灰色选项的提示反着读

原来印的是 `（不可选：机化率≥30%）`，试玩者的原话是
**「字面读起来像『达到这个数值就不能选』，可选项偏偏在你没达到时灰着，方向正好反了」**。

改成 `（不可选，需要 机化率达到 30%）`。技能同理。
这一条我上一轮刚改过（把英文 flag id 换成中文说法），却没注意整句的方向——
**换掉一个词不等于句子读得通，得整句念一遍。**

### ③ 一世终结后，重放脚本把当前世重复一遍

`_repro_line()` 的 bug，是我上一轮亲手写进去的：
这一世终结的那一刻就已经写进 `legacy["replay"]`，`state` 里再补一条就重复了。

试玩者不但发现了，还**自己拿 `--replay` 验了**：重复段用同一个种子开局，
疑云是 0/8 而原局是 2/8——世界记忆不同，重复段复现不出原局。
**他等于替我把「复现承诺」证伪了一次。**

修法：`st["over"]` 且 legacy 末尾已是同一段时不再追加。

### 顺带改的一处：牢狱之灾此前不掉血

`tax_audit` 如实申报失败原本只给 `heat+2`，文案却写着「牢狱之灾等待着你」——
**一句悬着的威胁，没有落点。** 补了 `hp: -1`，并把那句写完：

> 欠税的人不判刑，判的是「劳务折抵」——你在拆解场做了四个月，
> 把别人换下来的东西拆成能再卖一次的零件。出来的时候瘦了一圈。

〔这也是全篇唯一一处提到坐牢的地方。〕

### 文档

CLI 与 MCP 有一处**故意的差异**：CLI 不弹玩法菜单（人已经坐在终端前了）。
此前没写明，试玩者一上来用 CLI 就绕过了菜单。README 与 `TESTING.md` 都补了这一句，
并写清楚**试玩请走 MCP**——「转述得舒不舒服」这一类在 CLI 上根本测不到。

### 三条都加了回归测试

`试玩反馈三条回归通过（提示方向/重放不重复/CLI 可落笔）。`

### 一条没修的

跨世重复事件的成功文案一字不差，连玩三世有既视感。
这正是 `variants`（整幕变体）要解决的问题，但目前只有少数事件写了变体。
**不是 bug，是内容缺口**——记在这里，等有余力时按事件重要性补。

## 2026-08-08 · 改版：机化率即阵营（作者定案 B ＋ 湖是唯一出口 ＋ 删渡魂签）

**改版之前**：出生掷一个阵营，机化率在该阵营的区间里掷出来 —— **你是谁是运气**。
**改版之后**：机化率从 0% 开始、跨世累积、只涨不降；**阵营就是机化率落在哪一档**。

| 机化率 | 阵营 |
| --- | --- |
| 0% | 纯血誓约 |
| 1–39% | 心照不宣 |
| 40–69% | 明焰 |
| 70–100% | 飞升螺旋 |

这四档**正好是真相碎片原本的门槛**（0／<40／40-69／70-99／100），所以碎片一处没改。

### 三样新东西

1. **每一幕之后的改造机会**（`aug_offer_0..3`，按档取用，不掷骰）。
   **纯血于是变成了「每一幕都被问，每一幕都说不」** —— 它不再是抽到的出身，是一种坚持。
2. **跨档三问**（`lean_*_1/2/3`，四档各三题）。阵营由数字决定，**派系由这三题问出来**。
   每题两个选项各记一分，三题定归属。
3. **`aug_tier()`**：机化率 → 阵营。所有原有门控（`factions`/`subs`/`min_aug`）一字未动，
   因为这三样在新模型里都还在 —— 只是从掷出来的变成挣来的。

### 删掉的

**渡魂签整个删掉**（工具参数、文案、退回验证）。新模型里没有「出生阵营」可指定了。

### 两次实测逼出来的修正

**① 一世之内 0% → 81%，四档形同虚设。**
九幕九次机会、每次 +6~+26，一世就能穿过全部四档。两处修：
- **一世最多动三次刀**（`AUG_PER_LIFE = 3`）。每一幕仍然会问 ——
  **说不的人每一幕都被问，那正是纯血这条路的形状**；说过三次是之后身体要恢复期。
- **幅度整体减半**（现在是 +4~+13）。

实测曲线：`0 → 24% → 44% → 59% → 88% → 100%`，**五世走完**，四档各有戏份。

**② 到了 100% 就永远回不来 —— 一条真正的死路。**
原本只有「在湖边说对话」才会把身体归零；说错话、或者什么都不说的人，
机化率停在 100%，此生此世再也回不到纯血。

改法：**两口水都是湖水，都把身体交还给你** —— 差别只在你记不记得自己是谁。
这样作者那句「只有湖水能把 100% 变成 0%」字面上仍然成立，而死路消失了。
而且它比原来的写法更好：**忘川不是惩罚，是另一种归还。**

### 覆盖工具跟着改了

跨世累积之后，一条档案会一路飘到 100% 然后停在那里 ——
`--coverage` 只跑一条档案的话，实测 **40 个事件在 800 世里一次都没抽到**。

改成**模拟四种玩家，每种一份干净档案**：从不改造／只装小件／有大装大／随便点。
改完之后：**事件零死角，未触发回响 12 条** —— 和改版前的基线完全一致。

〔这件事本身值得记一笔：**改版会让测试工具失效，而失效的测试工具比没有更危险**——
它会给你一份「一切正常」的假报告。这次是覆盖报告自己把改版的副作用喊了出来。〕

### 验证

新增定向验证「机化率即阵营」八项：四档无缝、第一世必然 0% 纯血且开局先问三题、
三题各记一分并写回档案、每一幕都有改造机会且不点头就一直是纯血、
跨档立刻换阵营并问三题、跨世累积、湖是唯一的归零通道、渡魂签确已不存在。

事件 73 → 89（多出 4 个改造机会 ＋ 12 个三问）。六道门禁与 400 局回归全绿。

## 2026-08-08 · 第二轮试玩反馈（两条，都改了）

### ① 夜袭的拒绝分支没按子派系适配

试玩者的原话很准：**「第 2 世你是铁锤派，被骂『圣殿派的软骨头』很成立；
第 6 世你本人就是圣殿派，同样两句台词变成废话。」**

`purist_hammer_raid` 是纯血通用事件，那条拒绝分支写的是从铁锤派内部看出去的视角。

为此给引擎加了两样：

**一、变体可以按子派系命中**：`{"sub": "圣殿派"}`，和 `deed`/`seen`/`ach`/`aug` 同一套语法。

**二、只换选项、不换正文的「局部变体」不再吞掉回响。**
`_view` 原本一律 `echoes = v.get("echoes", [])` —— 理由是「整幕变体本身就是那条回响长成的」。
**但那条理由只对换了 `text` 的整幕变体成立。** 只换选项的那一幕还是原来那一幕，回响该照给。
改成：`v.get("echoes", [] if "text" in v else ev["echoes"])`。
〔这是我做第一条时当场踩到的 —— 加完变体，那三条 `hammer_run` 回响全没了。〕

圣殿派那一版的拒绝分支：

> 他没有骂你——骂一个圣殿派「软骨头」是骂不动的，你们本来就是靠念经站着的那一半。
>
> 「我知道你们那边怎么念。」他说。「念完了，门还是得有人踹。」
>
> 他把撬棍递给了下一个人。从那以后集合的名单上还有你的名字，
> 但名字后面那一栏——写着「留守」的那一栏——再没空过。

**对铁锤派是绰号，对圣殿派是名单上的一栏。** 同一次拒绝，两种摩擦。

### ② 灰港沉了，纯血终幕还在让你「去找传闻中的灰港」

试玩者提的是时间线：世界记忆里灰港已经沉没，选项却没变。

作者给的解法是设定层的，比改选项好得多：**灰港会无限复活。**
两处都加了。沉没那一幕的落点：

> 灰港是一把湿透了的钥匙，装在某个还活着的人口袋里。
>
> **只要还有人需要一个不问来路的地方，灰港就会在别处重新长出来。**
> 下一个灰港也许不在海边，也许天色很好，也许连「港」字都不占。
> **但所有需要它的人都会认得出它。** 名字是跟着需要走的，不是跟着地图走的。

纯血终幕那个选项用条件尾巴（`harbor_sunk ≥ 1` 才长出来）：

> 路上有人告诉你：灰港沉了，前些年的事。你问那现在去哪儿。
> 对方看了你一会儿，报了一个地名——不在海边，天色也不灰。「还是那个地方。」他说。
> **「只要还有人要找它，它就还在。换个门牌而已。」**

两条都加了回归测试。给 4.6 的简报也补了 `{"sub": …}` 这一行。

## 2026-08-08 · 第三轮试玩反馈（六条）＋ 作者推翻我的一处改动

### 作者定案：**答不对就永远在 100% 循环**（推翻我上一轮的改法）

我上一轮把「两口水都把身体交还给你」写了进去，理由是**说错话会锁死**。
作者的判断是：**那不是锁死，那是循环**——每一次上载都会重新打开一次湖门，
玩家可以一直试。而把「归零」这件事**只留给答对的人**，纯血才真的贵。

她说得对，我那条理由站不住：我把「循环」误判成了「死路」。改回来了。

现在的规则：
- **忘川带走记忆，不还身体。** 醒来仍然是 100%，仍然是飞升。
- **只有说对了话的那一口才把身体交还给你。**
- 下一次上载之后湖会再开门。**答不对，就永远在这个圈里。**

### 六条反馈，全部证实并修复

**A【中】跨档三问吞掉一个岔口。** 试玩者连复现两次，还直接指出了原因：
`offered` 标记在「跨档 → 三问 → 回正轨」这条绕路上没有复位。
修法比他建议的更彻底：**把复位点搬进 `_next_event()`** ——
新的一幕开始，这一幕的机会就还没给过，这是唯一正确的地方。

**B【中】「疑云」和「锚重」两个名字混用。** 状态条按阵营取名（`heat_label`），
战报块却写死了「疑云」。`_fx_digest` 现在收一个 `heat_name` 参数，和状态条同源。

**C【中】封档文案与词条携带矛盾。** 文案说「一个全新的、空白的魂」，
可 8 条词条按 100% 存活率全带进了新谱系。这是设计（词条存活率＝机化率），
**错的是文案**。改成：

> 封档带走的是**技艺**。你亲手写下的记忆词条不在其中——字是你自己刻的，档案收不走。

**D【低】新谱系的第一世显示成「第 6 世」。** 加了 `cycle_base`，
现在是「第 2 谱系 · 第 1 世（累计第 6 世）」。

**E【低】暴露结局把阵营记成旧的那一档。** 49%（已在明焰区间）暴露而死，
终局清点仍写「心照不宣」。原因是阵营对齐在 `_tier_check` 里，
而它排在死亡／暴露结算之后。**拆开了**：阵营立刻跟机化率对齐（`_apply_fx` 之后），
三问那一段仍留给 `_tier_check`（靠 `tier_pending` 传递）。

**岔口文案一世重复八遍。** 试玩者数得很细：0% 档一世 8 次一字不差，
而我预留的「工伤复检」变体要求 `deed: honest`，**纯血路线六世都拿不到，等于没有**。

两处修：
- 那个变体的门放宽成 `any`（诚实纳税／散过钱／替人瞒过／改写过规则／第四幕之后）
- **给条件语法加了 `{"turn": N}`**（本世第几幕），0% 档再写两版轮换：
  招工启事「优先考虑已完成基础神经索引者」、朋友换了一只眼睛非要你看。
  实测一世之内至少三种说法。

### 覆盖工具又一次自曝

改完之后 `--coverage` 报「23 个事件在 1200 世里一次都没抽到」。
原因：**`legacy["sub"]` 一旦定下终身不变，一条档案一辈子只见得到八个派系里的一个。**

加了档案轮换（每 12 世一份干净档案）。改完：**事件零死角。**

代价是未触发回响从 12 条涨到约 40 条（跨世事迹攒不起来了）。
**两害相权取前者**——「事件零死角」比「回响触发率」重要得多，
这条判断写进 `TESTING.md` 的基线说明了。

〔连续两轮，覆盖报告都是自己把改版的副作用喊出来的。**这个工具已经付清成本了。**〕

### 一条只记录不改的

试玩者观察到：心照不宣档那把 +10 的「不打算藏」每次加热度，
三刀全选再加几次失败就会被自己烫死（他第 3 世死在 49%）。
**这符合设计**（公开不藏有社会代价），暂不动。
如果之后想给「闷头往上走」留一条安全路，改的是文案里把两条路的代价点得更明显，
而不是改数值。

## 2026-08-08 · 湖的开场改成两个选项（作者定案）

**起因**：试玩者走到湖边，看见「你要什么。」这个开放性问题，**直接走开了**。
作者的判断很准——那不是他不会答，是**一个没有边界的问题在这个位置太吓人**。

### 改法

**第一步不再是问答，是两个选项：**

```
守卫看着你。他不问你是谁，也不问你从哪儿来。
他只等你开口。

  1. 「我干渴欲裂。」
  2. 沉默。什么也不说。

用 recite("1") 或 recite("2") 回答。
```

- `recite("2")` —— **当场给一个结局**（此前是静默消失：湖在下一次 `new_run` 时被清掉，
  玩家什么反馈都没有）。文案写清楚了两件事：**身体不还**，以及**下一次上载之后湖还在**。
- `recite("1")` —— 等价于说出「渴」，进入第二步；之后仍然是自由问答。

第二步保持自由问答**是有意的**：这一句是整个游戏留给「本来就知道」的读者的那扇门，
做成选项就等于把答案印在门上了。

### 金叶子提示

认渴之后，**在场听过临终复述那句话的人**（世界事迹 `heard_the_leaf`）多读到一行：

> 你舌尖压着一句背过的祷词。

**这不是提示答案，是提示「你身上有过这样一件事」。** 没听过的人一个字都不会多。

### 顺带

`recite` 的工具说明改了，写明第一步是两个选项、之后才是自由的；
也写明了走错那一口不还身体、但湖会再来。README 的湖那一节同步。

新增定向验证「湖的开场」四项：两个选项在、沉默有结局且不还身体、
金叶子提示只给听过的人、说全了身体归还。

## 2026-08-08 · 第六个结局：修船（作者定案）＋ 第四轮试玩三条

### 修船 —— 只给那个人一个人的结局

作者：**「让曾经收到过盲眼老人的《私人小型船舶紧急维修速成手册》的玩家
（不论在哪一世）才能修船。」**

夜间图书馆那个选项——**把兜里所有的钱掏出来塞给盲眼老人**——
换回的是一本卖不出去的破书。它在游戏里放了很多世，一次都没用过。

现在它是渡口的第六个选项。**不显示成「不可选」，它根本不出现。**
（显示成灰的就等于告诉所有人「这儿还有一个」，那就不是留给那个人的了。）

落点用的是老人自己那句话的下半截。他当初说的是：
「人一辈子不能读太多字。读到所有事物的所有可能性之后，你就再也做不出选择。」
封底那行铅笔字是：

> 「读到所有事物的所有可能性之后，你就再也做不出选择。
> **所以别读完。留一页，动手。**」

结局的落点：

> 档案没有烧，没有公开，没有被送走，也没有换一个看守。**它只是不漏了。**
>
> 访问日志的最后一行还在那里。身份栏空着，权限栏写着：正在阅读。
> 这一次，它下面多了一行新的。
> 身份栏仍然空着。权限栏写着：**正在修理**。

新成就「留一页，动手」`shipwright`。转世后的世界底色：
「渡口的木柱上钉了一块新板，颜色比周围浅一圈。没有人解释它是什么时候换的。船照常开。」

### 三条试玩反馈

**① 轮回档案缺了第 1 世 —— 数据没丢，是显示截断。**
试玩者猜是「历史写入/截断的 bug」，猜对了一半：`history` 里九条一条不少，
是 `legacy_info()` 只印最后 8 条。**不声不响地截断，比不截断更糟** ——
他据此以为记录丢了。改成：**第一世永远留着，中间省略，并且明说省了几条。**

**② 双栖结局到 100% 不封档、不进湖。** 他问是不是有意的。**不是。**
「保留一具巡检肉身」给 +20%，一个 80% 的人正好撞到 100 —— 于是既没有 `ascended` 标记
（不封档、不进湖），又因为岔口的门是 `aug < 100` 而**从此再也没有改造机会**，
谱系永远停在那里。

修法不是给它补封档（那会强行上载一个明确保留了身体的人），而是立一条规则：
**100% 是上载专有的数字。** 别的改造再堆也停在 99%。双栖那句也点明了：

> 你成了螺旋史上第一个「双栖者」——**档案上永远差一个百分点，而那一个百分点就是你留下的那具肉身。**

〔第一版上限写成 `min(99, …)`，把已经 100% 的人往回压了，当场被
「机化率倒退」那条不变式抓住。改成 `cap = max(99, old)`。**旧断言救了新代码。**〕

**③ `honest` 那个门是不是死的。** 他说「那个变体要求的 deed 可能根本没人拿到过」。
**这一条他判错了**：实测 300 世里 `honest` 拿到 32 次（约一成），`gave_it_away` 31 次。
稽查站「如实申报」成功就给。他九世没撞上而已。
而且那个变体的门**上一轮已经放宽**成了「任一」＋第四幕之后，现在必然可达。

### 主回归也得了覆盖工具当初那个病

改完之后自测报「已见事件 32/89、碎片 2/5」。原因和覆盖工具一模一样：
**机化率跨世累积，一条档案飘到 100% 之后再也下不来** ——
那 400 局实际只在跑「一个 100% 飞升玩家」。

主回归也加了档案轮换（每 12 局），统计跨全部档案合计。
改完：**已见事件 63、碎片 4/5、跨世事迹 100 类。**

〔同一个病，覆盖工具先得，主回归后得。**改版之后所有「长期累积型」的测试工具都要重查一遍**——
这条经验值得留在这儿。〕

## 2026-08-08 · 牌堆机制 ＋ 改装师三个变体

### 牌堆：从「加权随机」改成「一副牌」

试玩者的原话是**「基础事件池子不抗烦」**。原因量出来是硬的：
**通用事件只有 14 个，而一世要走 9 幕。**

从前每一幕从全部合格事件里加权随机抽 —— 池子小的时候会反复抽到同几个，
而且「重复」是概率问题，没有上限。

现在：**通用事件是一副牌。** 每一世发 `GENERIC_PER_LIFE`（4）张，
发过的不回堆，整副发完才洗。**「一副牌走完之前不会重复」从概率变成了保证。**

三处细节：

1. **洗牌是加权洗牌**（Efraimidis–Spirakis，`u^(1/w)` 排序）。
   时代骰偏爱的事件更容易排在前面 ——
   **时代的影响还在，只是从「更容易抽到」变成了「更早轮到」。**
2. **不合格的跳过但不弃牌。** `req_seen` 还没开门的那张牌回到堆里等这一轮的后面，
   而不是被消耗掉。
3. **派系那边没有牌堆。** 一条派系线本来就有 `req_seen` 串起来的顺序，再洗一次是添乱。
   剩下的幕数（9 − 4 = 5）正好够一条派系线一世走完。

通用与派系怎么穿插：按**剩余配额掷**，而不是「先四幕通用再五幕派系」。
任何一边空了就全给另一边。

实测 14 张牌、每世 4 张：一轮 3.5 世；八世三十二张里每张出现 2–3 次，分布很平。

### 改装师：三个变体 ＋ 三条回响 ＋ 两条技能之声

作者与 4.6 续写的第一批。改装师的弧线是
**兜售者 → 自我改装者 → 镜子收藏者 → 放弃镜子的人**；
镜子的弧线是**哈哈镜 → 碎了一半 → 七八面各不相同 → 一面也没有**。

装配时改的四处：

1. **「感知」这个技能不存在**（第三次了）。
   变体2「每面镜子前都站一会儿」→ **共情**；
   变体3「闭上眼用手摸自己的脸」→ **巧手** ——
   后者比原稿更贴：那一幕的题眼就是精度。
2. **难度整体上抬**（6/7/8 → 8/9/10）。这个游戏的检定区间是 8–12。
3. 技能收益归一（成功 +2、失败 +1），几处失败分支原本一点技能都不给。
4. `deed "x"` → `flag:x`。

### 一个只有装配时才看得见的坑

**换了 `text` 的整幕变体不继承基础事件的回响。**

改装师基础事件上原有两条回响，条件是「见过 ≥2」和「见过 ≥4」；
而变体从「见过 ≥1」起就接管了整幕 —— **那两条回响从变体上线那天起就再也不会出现。**

处理：
- 「和我想的一样。看到你走过来时，我就觉得你应该长这样」→ 搬进**变体2**（见过 ≥2 那一幕）
- 「他隔着镜子报价，从第四档说起」→ **退役**。
  它属于「他还在做生意」的那个世界，而变体3 的第一句是「今天不接活」。
  两句直接打架，留着就是让同一个人在同一幕里既收摊又报价。

这条已经写进给 4.6 的简报：**给基础事件写变体的时候，原来挂在它身上的回响要一起搬进去。**

### 验证

新增定向验证「牌堆与改装师」：一世之内不重发、一轮之内不重复、洗牌不丢牌、
三个变体各就各位（见过 0/1/2/3/7 次各读到该读的那一版）、
闭眼摸过脸的人在第三阶段多一条校准回响。

事件仍是 89（改装师是长在原有事件上的），修改表 1145 → 1186 条、83098 字。
覆盖 1600 世事件零死角。

## 2026-08-08 · 歌手三幕（作者手写稿）＋ 硬币 ＋「兜里有没有钱」

作者自己写的两个变体（烟嗓 / 最后几天）＋ 三条新回响。装配时新做了两样机制。

### 一、`"coin": True` —— 全游戏唯一一处与角色无关的判定

原稿：「替我扔一次硬币吧。正面就换机械声带，背面就保持原装。」

这个判定**不能是检定**。检定的意思是「你是谁决定了结果」，
而这一幕的重量恰恰来自反面：**一个人的下半辈子由一枚硬币决定，与你的技能无关。**
所以加了第四种选项形态（此前只有 `effects` / `check` / `gate`）：

```python
{"text": "扔。", "coin": True, "success": {…正面…}, "failure": {…背面…}}
```

五五开，不吃技能，也不受双六蛇眼影响。选项行上明写〔抛硬币，五五开。技能不算数〕——
**这一处必须让玩家事先知道，否则他会以为是自己没练够。**

跟着改的三处：`last_beat`（硬币的正面/背面）、门禁扫描的分支枚举、`docgen` 的抽取。
〔前两处漏一处就是「文案在源码里但抽不出来」，和回响没条件是同一类静默失效。〕

### 二、`flag:broke` ——「你身上现在有没有钱」

原稿在选项里写着【需要玩家身上有钱】。游戏没有金钱数值，也不该为这一幕新开一条。
改成一个**由已有文案自然产生**的本世状态：

| 哪一句已经说了你没钱 | 现在跟着记一笔 |
| --- | --- |
| 盲眼老人：「把兜里所有的钱掏出来」 | `flag:broke` |
| 稽查站 如实申报成功：「钱包空了」 | `flag:broke` |
| 稽查站 如实申报失败：「你没有钱」 | `flag:broke` |
| 稽查站 替码头工垫申诉费 | `flag:broke` |
| **叫歌手起来唱、并且付了钱** | `flag:broke` |

于是最后一条自己长出一个回路：**同一世里叫他唱第二次，你就付不出了**，
挨那一酒瓶（-1 体力）。这一下不是随机惩罚，是上一次的账。

### 三、变体3 · 空通道（这一幕是我补的，不是作者原稿）

作者那两版之后，歌手在四种结局里有三种已经不在通道里了
（换了机械声带走了 / 去了码头 / 换成真人声带认不出了），
**而这个事件还会被抽到**。留着不写就是让一个已经走掉的人天天回来上班。

补的是一幕短的：墙根空着，一个焦黑的圆坑，一只立着的空瓶子。
三种去向各挂一条回响（转播里那副没有沙的嗓子 / 码头卸货的号子 / 街角调子对嗓子不对）——
**用回响分岔，不用三个变体**，正文只写共同的那一部分。

〔这一幕随时可以删掉或换成作者自己的版本，条件是 `singer_gone` 或 `singer_dock`。〕

### 四、回响的搬迁（上一轮那条教训的第一次实战）

基础事件上原有的 `duet` 回响（「主动递了半个拍子给你」）在烟嗓那一幕里不成立——
他宿醉，没在唱。**没有直接搬，改写了一版**：
「他没抬头，用瓶底在地上磕了两下。两拍。」

作者新写的三条回响按覆盖范围分别装进变体1 和变体2：
`seen≥2`（黄手指、鞋底的圆坑）只在变体1；
`seen≥3`（经过这里不害怕）与「喝过酒」两条**两个变体里都要有**——
因为没一起喝过酒的人在 `seen≥3` 时仍然停在变体1。

### 验证

新增定向验证「歌手三幕」：弧线四档（本体 → 烟嗓 → 最后几天 → 空通道）、
没喝过酒的人不该看到告别、人走了就不再上班、
**硬币把技能拉满到 12 仍然是 120 次里 40–80 次正面**、
掏空过兜的人叫不动歌手、付过一次之后同一世再叫就付不出。

## 2026-08-08 · 身体税两幕（作者手写稿）＋ 一次抗烦体检

装了作者的 `tax_audit` 变体 1（换班）与变体 2（手检），三条新回响。
装配时按惯例改了三处：检定难度 7 → **8**（这个游戏的区间是 8–12，7 等于白送）、
技能收益归一（成功 +2 / 失败 +1，原稿几处一点不给）、`deed` → `flag`。

变体 2 的门是 `tax_hand`（指过他那只工伤的手），不是熬次数 ——
**这一条设计得很好，值得记下来**：手检那一幕之所以成立，是因为他先认得你。

### 顺带做了一次体检：现在到底抗不抗烦

作者问「十几个剧情、每世抽四个，抗烦吗」。量出来的答案：

| | 一世九幕里「以前没读过」的有几幕 |
| --- | --- |
| 第 1–4 世 | 7–9 幕 |
| 第 5 世 | 约 5 幕 |
| **第 6 世起** | **1 幕以下** |

**墙在第六世。** DeepSeek 跑到第九世说不抗烦，位置对得上。

但真正的原因不是通用牌只有 14 张 —— 14 张事件已经长出 **32 个不同场景**（变体的功劳）。
真正的原因在派系那一侧：

```
从不提升机化率：铁锤派 → 铁锤派 → 铁锤派 → 铁锤派 → 铁锤派 → …（十世不变）
随机游玩：      面具沙龙 → 平权阵线 → 群智派 → 群智派 → 群智派 → …（第四世起锁死）
```

**机化率只涨不降 ⇒ 到顶之后阵营再不变 ⇒ `legacy["sub"]` 终身不变。**
于是从第三四世起，九幕里那五幕派系戏永远是同一支的同五幕。
**一份档案十世只见得到 2–3 个派系，而全城有八个。**

### 改法：同一档待满三世，把三题重问一次

`LEAN_REASK_LIVES = 3`。不是引擎替他换派系 —— **是再问一次，他自己答出来是什么就是什么。**

## 2026-08-08 · 河堤 · cc（作者手写稿，四幕 ＋ 一条例外规则）

作者写的第一条**高机化专属长线**，也是整个游戏里第一条**会被永久关闭**的线。

- 难度：追孩子 坚忍10、调查 街智11、问名字 共情11、**牵手 共情12**、

- 「唱一首记不清的歌」原稿标注【需要见过地下通道歌手大于等于3次】——
  **引擎原先没有选项级的 `seen` 门**（事件级的 `req_seen` 早就有）。加了
  `req: ("seen", "old_singer", 3)`，并给灰掉的选项配了中文说法表 `EVENT_NAMES`，

### 变体4「空河堤」是我补的

作者定的规矩：**动过那台手术之后，无论成没成，cc 就不在了，换一世也不行。**

对岸没有人，水面平到照得出你自己的脸，**那张脸和上一次来时一模一样，一天也没有老**。
三个选项都围着草结转（找一个 / 自己打一个 / 走了）。
两条回响按去向分岔：银白色的东西跑得极快 ／ 荒滩那块地寸草不生。

### `LAKE_FORGETS`：世界记忆的第一条例外

**「必须用湖水复活一次，cc 跟着一起复活，但不带记忆从 0 次见面开始」—— 能实现，而且干净。**

世界记忆不衰减是这个游戏的地基（飞升封档都清不掉它）。所以这条例外必须写成
**白名单**，而不是「除了 X 都清掉」：

```python
LAKE_FORGETS_DEEDS = ("cc_glimpse", "cc_named", …, "cc_gone", "child_farm")
LAKE_FORGETS_SEEN  = ("riverbank",)
```

`_lake_forget(world)` 挂在两处**「喝对了水」**的落点上（人的那口和狗的那口），
**忘川那口不挂** —— 答错的人连这个都得不到。

于是这条线的完整形状是：
**走完四幕 → 手术 → 她不在了 → 你得再把自己换到 100%、死透、在湖边答对那句话
→ 醒来是 0% 的血肉，河堤重新有人跑，而她不认识你。**

〔她回来了，代价是你们从第 0 次开始。**这一条是这个游戏关于「记忆是谁的」
那个题目最狠的一次应用**，我没有改动它的任何一个字。〕

认真玩的人练得起来。这个稀有度是对的：四幕长线不该人人走完。

## 2026-08-08 · 第七轮试玩反馈（四条）

**① 跨档换阵营，那一栏必须归零 —— 作者定案，也是真 bug。**

〔副作用值得记一笔：清零发生在暴露判定之前，

## 2026-08-08 · 楼下的歌声（作者手写稿）＋ 剧情退场 ＋ 全书终

作者的第二条高机化专属长线，三段：楼下的合唱 → 敲错门的人 → 床头那只手。
也是**第一条会讲完的线** —— 走到最后做出那个动作之后，它从此不再出现。

### 装配时新做的三样

**① `retire_deed` —— 让一条线讲完之后退场。**

作者的话：「所有回响和新剧情都跑完了以后，这个剧情就彻底退场吧？」

写法是 `retire_deed="hymn_done"`，世界记忆里有了这一笔，这一幕再也不进随机池。
**理由不是省事，是结构：一条有始有终的线走到终点之后还继续被抽到，
等于把结尾拆开来重演一遍。**

**② 第七道门禁 `lint_retire` —— 退了场的线不能把别人的钥匙带走。**

作者自己在提案里就点到了这一点：「注意有的剧情需要其他剧情选了特定选项，
所以那个对应的剧情也展示不能删除」。这句话正好可以写成一条机器能查的规则：

> **如果某个 flag 只有一条会退场的线给得出来，而别的幕在等它，
> 那么这条线一退场，那些幕就永远开不了门。**

外加一条自查：退场用的那一笔必须由这条线**自己**写得出来 ——
否则它要么永远不退场，要么根本没机会讲完。

**③ `EPILOGUE` —— 全书终。**

条件是两条同时成立：**每一条会退场的线都退了场**，**并且渡口那道题已经答过一次**。
只念一次，念完这一世照常开始。排在终局判定**前面** ——
渡口每隔几世会重新浮现，排在后面的话它永远轮不到。

〔为什么要加「答过渡口」这一条：现在只有一条线会退场，
不加的话，讲完这一条就会跳出「所有故事都讲完了」，太早。
**这一条同时也是对的：全书终的听者不是玩家角色，是这台机器 ——
它该排在这个游戏自己的结局后面。**〕

## 2026-08-08 · 退场表：把六十条弧线全部接上（Fable 5 指出）

上一轮我做了退场机制，却只给**一条**线挂了标记 ——
而「全书终」说的是「所有会讲完的故事都讲完了」。
Fable 的原话：「彩蛋屏说着所有故事都讲完了，而狗、河堤、八条线还在照常轮换。」
**这是我自己定的意图，自己没做到。**

### 判据只有一句话：这一幕是天气，还是一条线？

- **天气**：夜市、渡轮、停电、夜图书馆、中介所、深夜敲门、残响、岔口、三问。
  **永不退场。** 它们不是故事，是这座城每天都在发生的事。
  全书终自己那句「还没讲完的那些，本来就不打算讲完」说的就是它们。
- **弧线**：讲完就退场。**六十条。**

### 两种写法，一张表

新加了 `retire_seen`（见过 N 次就算讲完），和原有的 `retire_deed`（做出终点动作才算讲完）
并列。全部退场条件收在 `RETIRE_POLICY` 一张表里，不散在六十个 `_ev` 参数中间 ——
**这张表就是「这个游戏一共有多少条线、每条在哪儿结束」的目录。**

| 谁 | 条件 | 为什么 |
| --- | --- | --- |
| 八条派系线 ×5 幕 ＋ 四档阵营通用 | `seen 3` | 读三遍就够了；一条线一世走完，三世等于三种走法 |
| 改装师 / 老歌手 / 身体税 | `seen 6` | 变体开到 ≥3，得让最后一版被读到几次 |
| 狗 | `seen 8` | 六个变体，全游戏最长 |
| 电梯传教士 | `seen 4` | **≥2 是硬下限**：圣殿派「跪」那一幕等着它 |
| 楼下的歌声 | `deed hymn_done` | 有明确终点动作 |
| 河堤 | `deed cc_closed` | 空河堤走过一次就关；**忘川会把它冲掉，cc 从头再来** |

### 退场门禁跟着长了一条

`retire_seen` **必须 ≥ 别人对这一幕的 `req_seen` 门槛**。
这条能证明是安全的，理由很简单：**`seen` 计数只增不减** ——
门槛够高，后面那一幕的钥匙就永远还在手里。
（老歌手 `seen 6` ≥ 河堤那首歌要的 3；电梯 `seen 4` ≥ 圣殿派要的 2。）

### 讲完之后世界是什么样

- 派系那一侧空了 → 全部落到天气上，一世能走五六幕，然后**提前走到终幕**，
  多一行：「这座城今天没有新的事发生。你径直走到了这一世的尽头。」
  **早退不是 bug，是那张退场表走到尽头的样子。**
- 顺手修了一处：牌发干的时候原先直接取 `FINALES[faction]`，
  **绕过了改道表** —— 狗和灰港的终幕会被这条捷径吃掉。现在改道表照走。
- `legacy` 里印进度：「讲完的线：12/60。讲完的不再出现；
  夜市、渡轮这些不算线，它们是天气。」
  **不印的话，玩家只会觉得「怎么越玩越空」。**

### 验证

新增「退场表」五项：六十条线都挂上了、**八条派系线一条不漏**、天气不退场、
退场不锁后面的门（抄经课退场之后密室仍然开着）、
以及**全部讲完之后仍然走得完一世**且档案里印着进度。

### 退场表上线之后炸出来的一个老 bug：牌堆会翻倍

装完退场表跑长局，**第 25 世之前每世 0.02 秒，第 26 世 4 秒，第 27 世 58 秒。**

根因在牌堆的发牌循环里，而且是我很早以前写的：

```python
for _ in range(len(deck) * 2 + 4):
    if not deck:
        deck = self._reshuffle(legacy)      # 洗回来整整一副
    eid = deck.pop(0)
    ...
    held.append(eid)                        # 跳过但不弃
legacy["deck"] = held + deck                # ← 这一行
```

一幕里**一张合格的牌都没有**的时候，循环会把整副牌洗回来再走一遍，
于是「跳过但不弃」的那一摞和洗回来的那一副拼在一起写回去 ——
**牌堆每发一次干牌就翻一倍。** 第 27 世的牌堆里同一张牌有几千份。

**这个 bug 一直都在，只是从前「一张合格的牌都没有」几乎不会发生。
退场表让它变成常态，它才露头。**〔这条值得记住：
**新机制最先撞坏的，往往是旧机制里那个「几乎不会发生」的分支。**〕

修法两处：循环改成「整副最多走一遍 ＋ 最多洗一次」，写回时 `_dedupe` 保序去重。
断言写在自测里：**牌堆张数不得超过牌的总数，且不得有重复。**

改完：两百世每世稳定 0.04 秒，牌堆恒定 16 / 8 张。

### 实测：一份档案能讲完多少

| 玩法 | 一百二十世之后 |
| --- | --- |
| 随机（有刀就动） | 20/60 —— 冲到 100% 就锁死在飞升螺旋那两支 |
| 永远拒绝改造 | 18/60 —— 卡在 8%，把心照不宣那一档**整档讲完了**（灰港＋面具沙龙＋通用三幕） |

**这正是这套设计该有的样子：一份档案讲得完它待过的那几档，讲不完全部。**
六十条全部讲完要走遍四档 —— 而唯一能往回走的路是湖水。
〔纯血那一档最难：`aug` 必须恰好是 0，而好几个事件本身就会给机化率。
**圣殿派和铁锤派的线是全游戏最难讲完的两条**，这一点和它们的教义正好对上。〕

「朋友的新眼睛」是**岔口的一个变体**，而岔口本身永远不能退场
（它是机化率唯一的入口）。所以退场这件事得能挂在变体上：

- `world["var_seen"]` 按 `事件id#变体序号` 记数，一世一次，在结算时并进世界记忆
- 变体里写 `"retire_after": 3`，`_variant_idx` 跳过讲完的那一版，**往前找上一版**

### 退场门禁跟着长了两条

**① 新检查：退场会不会把自己的回响变成死文案。**
「见过 N 次就退场」之后，条件写着「见过 ≥N 次」的回响和变体永远轮不到。
这一条当场抓出三处：

## 2026-08-08 · 见底之后：临终，和两种落幕（作者定案）

试玩报回来两条，**两条都是同一件事的两半**：退场制走到尽头，一份档案会「干」——
一幕都发不出来。

### ① 0% 纯血见底会永久锁死（连岔口都不出现）

**这是真 bug，而且是死锁**：岔口只在**一幕结束之后**才给，
而一幕都发不出来的时候，岔口自然也永远轮不到 —— 机化率再也涨不上去，
纯血那档的内容又全讲完了，档案卡死在原地。

作者定的解法比修 bug 好：**给他最后一次选择。**

```
「生、老、病、死。你以凡人之躯穷尽世间一切可能。」
千千万万次，你回到了临终的病床，这也是你出生的地方。
  1. 接受改造，活下去
  2. 拒绝改造，死去
```

- **拒绝** → 落幕：「亲爱的人类，晚安。」这一份轮回档案到此为止。
- **接受** → 机化率往上走一档，三问重问，纯血那条路从此关上
  （机化率本来就只涨不降，不用另加锁）。
- **喝湖水又变回纯血、而且仍然是干的** → 直接接到同一句。
  〔这一条是白来的：湖水把 `aug` 归零，下一次开局的见底判定自然会撞上它。〕

### ② 金叶片链被检定失败锁死之后，也该有自己的结局

作者判它「是对的」——**不是所有的门都该有第二把钥匙。**
但锁死之后世界不该只是空转，所以给了另一段落幕：

> 「循此苦旅，以达繁星。」
> 「向内，向外。」
> 「忒修斯之脑发射着思想的探针，直到群星尽头。」

**两段落幕的分界线是身体**：见底时机化率是 0 的走临终（他还有得选），
动过刀的直接落幕（没有回头路，也没什么可选了）。

### 装配时的几处

- `_is_dry()` 用**这一世开头**的状态问「还发得出一幕吗」——
  `used_events` 清空再判，所以答案只取决于退场表和门控，
  不取决于这一世已经走过什么。
- 见底判定排在**三问前面**：都没戏可演了，还问「你更像哪一派」是滑稽的。
- 落幕之后再调 `new_run` 只把那一幕再念一遍，并告诉他删 `saves/` 才能重来。
- 断线续命放行 `deathbed` 状态（此前它会因为 `pending` 不是事件 id 被判作废档）。
- CLI 落幕之后直接退出，不在那儿转空圈。

## 2026-08-08 · 见底判定的边界：本支讲完 ≠ 这一档讲完（DeepSeek 抓到）

**新版本的边界 bug，而且是我上一轮亲手引进的。**

见底检查排在三问重问**前面**——理由当时写得很漂亮：「都没戏可演了，
还问『你更像哪一派』是滑稽的」。**但它把一件事当成了两件事：**

> 当前派系线退完了 ≠ 这一档没戏了。
> **同阵营还有另一支。** 本该重问三题换过去，却被见底检查直接判了落幕。
> 一条完整的派系线（五幕）就这么被吞掉了。

### 改法（作者定案）

见底之后先问一句：**换一支还有没有戏？**

| 情况 | 结果 |
| --- | --- |
| 另一支还有戏 | **重问三题**，让他自己选换不换 |
| 答完还是这一支 | 那是他自己选的 → 落幕 |
| 另一支也没有了、而且**一条不剩** | **全书终**（真·忒修斯之脑结局） |
| 另一支也没有了、但还有别的档没讲完 | 繁星落幕 |
| 见底时机化率是 0 | 临终一问（照旧） |

`_dry_curtain(allow_lean=True/False)`：三问**之前**允许「换一支」这个答案，
三问**之后**不允许 —— 否则「另一支还有戏」会把落幕永远推掉，变成死循环。
〔第一版就是这么写的，自测当场吊死在那儿。**这类循环靠读代码看不出来，
靠一条会挂的断言看得出来。**〕

### 顺带把结局的层级理顺了

- **全书终**：一条不剩。它现在有两个入口 —— 老的那个（渡口答过一次 ＋ 全部退场），
  和新的这个（见底时发现一条不剩）。后者不要求答过渡口 ——
  **一个把六十八条线全讲完的人，不该因为没走到渡口而只拿到「繁星」。**
- **繁星**：这具身体没有别的路了，但世界还有没讲完的。
- **晚安**：0% 的身体自己选择不再往前。

### 验证

新增两项：本支讲完时该重问三题（而不是落幕）；答完还是原来那一支才落幕，
答成另一支就接着演。**两项都用同一份「灰港讲完、面具沙龙整条还在」的档案跑**，
分别答成两边。

## 2026-08-08 · 后半程减重（DeepSeek 的性价比清单，全做了）

反馈只有一句：**后半程重复率太高，很疲惫。** 他给的招按性价比排了序，逐条落地：

### ① 岔口：连着拒绝三次，这一世不再问

「要不要再往前一寸」每一幕问一遍，而机化率只涨不降 —— 后半程玩家永远在拒绝。
**这是全游戏最大的一坨噪音。**

`AUG_DECLINE_CAP = 3`，和「动过三次刀要恢复期」完全对称：

> 〔你连着拒绝了三次。这一世不会再有人问你。〕

**是「连着」，不是「累计」** —— 点过一次头就重新数。
〔第一版写成累计，当场把 `aug_offer_0` 的两个后期变体变成死文案：
拒绝三次之后再没有岔口，而那两个变体挂在第 6、8 幕上。
所以岔口的三个变体也跟着改了节奏：第 2、3、4 幕。**改节流阀之前先看谁挂在它下游。**〕

### ② 熟悉度压缩推广到所有事件

岔口早就做了「第二次起只给一行」。现在同一个机制给全部事件：
**同一幕见过 `FOLD_SEEN = 3` 次之后，场景只留第一行。**

```
酸雨敲打夜市的防水布，你沿着众多小摊组成的避雨长廊前行。……
〔这一幕你已经走过几回了。场景略。〕

【回响】小贩耐心地等你拿主意。等着等着，他把那枚芯片又往你手边推了推。
  1. …  2. …  3. …
```

**折的是重复的那部分，回响、技能之声、选项一个不少** ——
而回响恰恰是每一次都不一样的那部分。

### ③ 三问重问先问一句「变了没有」

同一档每三世重问同样三题，后半程玩家能把选项背下来。
现在重问先走一幕 `lean_recap`：

> 同样的三个问题又摆到面前。你已经答过一次了。
>   1. 答案没变。
>   2. 重新答一遍。

〔埋着一个坑：`_finish_lean` 是按 a、b 计分判派系的，
而「答案没变」一题都不记分 —— **0 比 0 会被判成「第二支赢」，人被悄悄换了派系。**
补了一条：一题没答就什么也别动。〕

### ④ 「早退」那一行跟着剩余条数走

同一句话在最后十几世每世念一遍是情绪杀手。现在：

| 还剩 | 那一行 |
| --- | --- |
| >10 条 | 这座城今天没有新的事发生。你径直走到了这一世的尽头。 |
| ≤10 条 | 故事越来越少了。 |
| ≤3 条 | 你隐约觉得，下一世可能是最后一次了。 |
| 0 条 | 没有了。一件也没有了。 |

**免费把 grind 变成铺垫。**

### ⑤ 退场次数 3 → 2

八条派系线 ×5 幕 ×3 次是 grind 的大头。压到 2。
〔个别几幕留 3：它们自己有一条「见过 ≥2」的回响，退早了那条就成死文案 ——
`lint_retire` 会替你查这一条，不用自己记。〕

### 他还提的一条我没做：全书终提前

他建议「全部线至少见过一次 ＋ 所有 deed 线完成」就算全书终，不必等 68 条全退。
**没做，理由是那段文字第一句是「所有的故事都讲完了」——
提前放它就是让它说谎。** 减重靠上面五条已经足够；
把 3 压到 2 相当于把 grind 直接砍掉三分之一，而不用动那句话的意思。

一份随机档案，六十世：

| --- | --- |
| 前十世 | **5872 字** |
| 后十世 | **1506 字** |

**后半程的篇幅只剩前半程的四分之一** —— 而砍掉的全是重复的那部分。

**改条件的同时改那句话，谎就不成立了。**〕

`legacy` 里的进度也跟着换成新口径：「走过的线：N/68；已经讲完的：M。」

### 换了门槛之后，机器立刻撞出三处锁死

这三处**在旧门槛下都不算 bug**（旧门槛本来就近乎走不到），
新门槛把它们全变成了硬伤。

#### ① 0% ↔ 100% 来回跳，中间两档一辈子遇不到

见底那一世**一幕也发不出来** —— 而「要不要再往前一寸」是每一幕之后才问的，
于是岔口偏偏在最需要它的时候问不出口。结果：一份走干了低档的档案只剩
「把自己交上去」一条路，上去就是 100%，湖把它送回 0%，再走干，再上去。
**明焰和飞升那两档的戏，它一辈子也遇不到。**

所以「走不动了」现在有两版。上面那一档还有戏时给的是：

> ─── 走 不 动 了 ───
> 这一档的事，你都经过了。
> 再往前没有路——除非再改一次，改得比以前都多。
> 但世界还没有讲完。
>   1. 再往前一寸。（换一副身体，换一档人生）
>   2. 到此为止。

选 1 直接跨进上面那一档，三问重新问，这一世接着开始 ——
和临终那句「接受改造，活下去」是同一个动作，只是跨的是一整档。
**已经在最上面一档了才回到原来那一版**（交上去 → 封档 → 湖）。

#### ② 金叶子那条路的两把钥匙会被退场带走

新门槛要 `hymn_done`，而这条链的入口只有两处发钥匙：

- `entered_chapel` —— 只有电梯传教士那一幕给（见三次就退场）
- `denied_the_leaf` —— 只有传教士临终那一幕给（见两次就退场）

**一个从没跟他上过三十九楼的人，第三次之后就永远拿不到钥匙了，
而他不会知道自己失去了什么。**

退场表新增第三种写法 `keep_until`：

```python
"elevator_preacher": {"seen": 3, "keep_until": "entered_chapel"},
"preacher_death":    {"seen": 2, "keep_until": "denied_the_leaf"},
```

读作：**这一幕手里攥着别人的钥匙，钥匙没交出去之前它就还不能走。**
交出去之后，照原来的次数退场。

#### ③（记一笔，没改）疑云门槛会被见底检查跳过

灰港的雾夜要疑云 ≥3，而「这一档还发不发得出戏」是拿**这一世开头**的
疑云问的 —— 开局疑云是 0 的那些世，它不算数。
不是锁死（绕一圈还回得来），但**它是机器最后没走完的那一条**。

### 实测：三个结局各要几世（新门槛）

| 结局 | 怎么走 | 几世 |
| --- | --- | --- |
| **晚安** | 一路拒绝改造，把 0% 那一档走干，临终选「拒绝」 | **14–35 世** |
| **繁星** | 随便把当前这一档走干，选「到此为止」 | **18–26 世** |
| **全书终** | 每条线走一面 ＋ 走完金叶子那条路 | **25–46 世**（八份档案里跑成五份） |

没跑成的那三份全部卡在同一条上（灰港的雾夜，见 ③），
而且卡的是**机器**：它每一世都空手落笔，从不留词条，
所以到了心照那一档身上什么也没带，疑云永远起不来。

〔旧门槛下这一栏是「四百世没走到」。**降门槛这件事是有效的。**〕

## 断线重连：把「续档」补齐成「接得上」（2026-08-11）

> 起因是第一份来自外面的玩家反馈：
> 「如果 CLI / MCP 的断线续档和当前世恢复能再稳一点，会特别适合这种跨很多轮、
> 长期玩的体验。因为这游戏最珍贵的东西恰好就是『连续性』。」

查下来**存档一直是好的** —— `saves/current.json` 每次 `choose` 之后原子落盘，
`Game.__init__` 起来就恢复。缺的从来不是存档，是**接的那一手**：

| 洞 | 原来会发生什么 |
| --- | --- |
| `new_run` 不看有没有进行中的一世 | 重连之后 AI 丢了上下文，照文档调 `new_run` —— 一世好端端躺在盘上，被一句新的开场白盖掉，而且**不入档案，等于没活过** |
| `run_cli()` 开头无条件 `GAME.new_run()` | 终端玩家按 `q` 走开，下次进来那一世就没了。存档躺在那儿，没人来接 |
| 旧档因事件表变更作废时静默丢弃 | 玩家 `git pull` 一下，手上那一世凭空消失，还以为是自己弄丢的 |
| 没有任何地方告诉 AI「重连先调 status」 | 它不知道有这条路 |

改法：

- `Game.in_progress()` / `resume()` / `abandon()` / `take_note()` 四个小方法。
- **MCP 的 `new_run` 先过一道闸**：手上有没走完的一世就把那一幕原样还回去
  （状态条 ＋ 场景原文 ＋ 选项），不开新局。要弃得写明 `new_run(abandon=true)`，
  弃掉的一世不结算、不入档案、不占世数。
  这道闸**只拦 MCP 那条路** —— 沿用 `REQUIRE_MODE` 的先例：CLI 那边人自己
  坐在终端前，自测与 `--replay` 要的正是「一句 `new_run` 就重开」。
- **`run_cli()` 开头改成先看有没有档**：有就打印 `status` 接着走。
- 旧档作废时 `clear_current()` ＋ 攒一句提示，下一次 `status` / `new_run` 说出来
  （只说一次）。历世档案不受影响，这句话里要写明。
- `status` 的工具说明、`new_run` 的工具说明、`initialize` 的 `instructions`
  三处都补上「断线重连先调 status」。**这三处是 AI 唯一读得到的说明书。**

自测新增第 ⑤ 组断言（走 `handle_request`，即真的从 MCP 那条路进）：
重启捞得回同一世 / `new_run` 盖不掉且还得回选项 / `status` 还得回原文 /
明说才弃且不占世数不入档案 / 旧档作废会说一声且只说一次。

〔另记一笔，与引擎无关：那位玩家撞上的 **GitHub 503** 不是游戏的毛病，
是连接器现抓文件时对方限流。`INSTALL.md`／`开始玩.md` 现在都写明了更稳的路：
**打包成 zip 直接上传给 AI**，别让它现去抓。〕

## HTTP 桥：让接不了 stdio 的客户端也能玩（2026-08-11）

> 起因是仓库的第一个 fork。有人在 `101fb8f` 之上加了 52 行
> `http_bridge.py`，头一行写着 `"""Wrap theseus-brain stdio MCP as
> Streamable HTTP for kelivo."""` —— **有人想在手机上玩。**

那一版的思路对（起子进程跑 `server.py`，HTTP 收到的 JSON 喂给标准输入，
读回一行），但会死锁。跑出来的：

```
POST notifications/initialized  → 超时，永远挂着
POST tools/list（之后）          → 也挂住了
```

MCP 客户端握手完必发一条 `notifications/initialized`，**这条不带 id，
按协议不该有回复**，`serve_stdio` 也确实不回它。子进程方案却无条件
`proc.stdout.readline()`，于是永远等下去，而且卡的是那把 stdout 锁 ——
**一条握手消息报销整座桥。**

我们自己这一版换了地基：**不开子进程，直接 import server 调
`handle_request`。** 管道那一整类毛病（死锁、stderr 管道写满、
子进程僵尸）连根去掉。

- 不带 `id` 的通知照 JSON-RPC 回 `202` 空正文，不等回话。
- 会话：`initialize` 时发回 `Mcp-Session-Id`，`DELETE /mcp` 结束会话 ——
  **只清内存，存档留在盘上**，同一个 id 连回来那一世原样还在。
- `--isolate` 每会话一份存档（`saves/http/<sid>/`）。默认共用是有意的：
  自己在家用，手机接的就该是桌面那条世系。**但对外监听时不开它，
  所有人共用一条世系** —— 对这个游戏来说那不是小事，所以启动时会警告。
- `--token` / `Origin` 校验（默认只放本机，MCP 规范点名要的那条防
  DNS rebinding）。对外监听而没设令牌时同样警告。
- 存档路径是模块级全局，每次请求前按会话换绑，与 `run_selftest` 里那套
  `keepN` 同源；引擎有全局状态，所有调用在一把锁里排队。

`http_bridge.py --selftest` 拿真的 HTTP 打自己，十一条：
握手拿得到会话 id／通知回 202 且不卡／卡过之后还能用／隔着 HTTP
`new_run` 也盖不掉进行中的一世／两个会话互不串档／令牌错回 401／
外来 Origin 回 403／坏 JSON 回 400／根路径健康检查与 `/mcp` 的 GET 回 405／
DELETE 不删档／**自测自己不碰真的 `saves/`**。

〔最后那一条是补上的：第一版自测把隔离目录写进了仓库里真的 `saves/`。
没伤到 `legacy.json`，但那种事不该发生，所以它现在是一条断言。〕
